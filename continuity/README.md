# INVENTHOR Continuity System

Purpose: let a new chat, a different AI/provider, or a restarted Brain continue work without rebuilding context from scratch.

The canonical continuity record lives in INVENTHOR, not inside any provider conversation.

## Mandatory read order for every new AI/session (26 Oct 2026)

1. Read `system_constitution/ACTIVE_PRODUCT_ARCHITECTURE_20261026.json` and `CONTINUE_HERE.md` for the **only current five-system owner scope**: INVENTHOR, OPERATOR, ORGANIZER, STUDIO_DESIGN and QA_FACTORY (QA=Fabrika).
2. Get the **exact CURRENT canonical TASK_ID, PROJECT_ID, live revision, owner/lease and evidence** from trusted native Main/Organizer. Stop mutation and report a real blocker if inaccessible.
3. Read the actual task-specific checkpoint/handoff plus dependency/acceptance data, then choose one smallest permitted finite task; do not duplicate terminal work.
4. Only for historical context, inspect `continuity/continuity_manifest.json`, dated project records and `continuity/idea_pool.json`. **They are reference snapshots, NEVER current live priority or a writable cloud ledger.**
5. After native verified execution, record real result, completed/remaining/checkpoint and release the actual task lease. No invented install or QA verdict.

## Write rule

After a meaningful decision or task milestone, update the **existing native Organizer canonical project/task/event/checkpoint** under a fresh lease. GitHub reference documents may be updated separately with sanitized non-authoritative summaries; never write a second task truth here.

Do not copy entire chat transcripts into continuity state. Store compact structured facts, decisions, evidence references, blockers and next actions.

## Provider-neutral rule

The current authorized roster GPT, Codex and INVENTHOR uses the **same native Organizer task-scoped handoff**; future providers are deferred and must not be self-enabled. Provider-specific chat history is optional context, never canonical project truth.

## Operator rule

Windows Operator is execution-only. It may mirror current task state and evidence locally for resilience, but INVENTHOR continuity remains canonical.


## Standard software vocabulary

Use the names in `STANDARD_TERMINOLOGY.md`: System of Record, Project Registry, Work Item Backlog, Work Queue, Event Log, Checkpoint, Handoff Packet, Architecture Decision Record, Artifact Registry, Evidence Store, Local Replica and Replication.

## Replication

INVENTHOR Main is the System of Record. Windows Operator is an execution Local Replica. Cloud may hold a synchronized replica for cross-device/provider continuity. Provider chats are never canonical state.

The existing INVENTHOR Main desktop backup is a bootstrap source and must be inventoried read-only before import.
